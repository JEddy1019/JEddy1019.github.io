Privacy policy

Effective November 12, 2026 · Owner-operated personal assistant

Timmy uses connected data to help its owner manage tasks and understand recorded commitments. This policy distinguishes the assistant from this public information site.

Google information accessed

With the owner's consent, Timmy reads the list of accessible calendars for source selection, event details for requested dates and free/busy information from selected calendars. Event details can include titles, times, all-day dates, links and the owner's attendance status. OAuth credentials enable these reads. The current Google scopes are calendar.calendarlist.readonly, calendar.events.readonly and calendar.events.freebusy.

How the information is used

Calendar information supports requested event summaries and time-management conversations alongside tasks and the owner's reported energy. Timmy's current Calendar integration does not create, edit or delete events. Separate task actions can update the owner's task system when authorized.

Timmy does not sell Google user data, use it for targeted advertising or use it to develop or train a general-purpose AI model. Google API data is handled under the Google API Services User Data Policy, including its Limited Use requirements.

Processing and service providers

The assistant runs in the owner's Hermes environment. Model processing is not entirely local: relevant prompts and tool results can be sent to the configured AI provider to answer the owner's request. Telegram carries the private conversation, and Notion stores the connected task records. These providers process information under their own terms, account settings and privacy policies.

Calendar details included in assistant conversations can therefore be processed by the configured AI provider and appear in Telegram replies. They can also remain in conversation records and the owner's independently retained agent archive. This information website does not receive the assistant's Calendar tokens, task records or conversation contents.

Storage and retention

The active Google OAuth credential is encrypted for the owner's Windows account using Windows DPAPI and stored outside the note vault. Calendar selections, bounded API usage counters and verification records are stored in the owner-controlled environment. Conversation records and tool activity are retained through Hermes and the existing Agent Memory capture system. Owner-requested notes and task records can persist in their respective systems.

No universal automatic deletion period is promised. Retained records and backups can remain until the owner removes them through the relevant system. External providers apply their own retention rules. Revoking Google access does not automatically delete information already retained in conversations, task records, notes or backups.

Choices, revocation and deletion

The owner can change the permitted calendar selection through the local setup process or revoke Timmy's Google access in Google Account connections. Revocation prevents continued authorized reads once the existing authorization becomes unusable; it does not recall already delivered replies. Requests to inspect or remove retained assistant data should be made to the operator through the existing private assistant channel or the support contact shown during Google consent.

Visitors to this website

These static pages have no analytics scripts, advertising, forms, account creation or browser storage. When hosted on GitHub Pages, GitHub receives ordinary web requests and logs visitor IP addresses for security. See the GitHub Privacy Statement. Following an external link is subject to that destination's own data practices.

Changes and contact

This policy will be updated when Timmy's connected-data practices change. The effective date appears above. The operator's support contact is provided in the Google consent configuration; existing users can also use their private Timmy conversation to raise data-handling questions.
